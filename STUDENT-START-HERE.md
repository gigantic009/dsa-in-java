# Start Here — Student Guide

Welcome! This repository is a free, self-paced Java Data Structures & Algorithms course. You do not need to purchase a course to use this learning path. The material is being improved continuously; read this guide and the topic lesson before relying on any individual solution.

## If this is your first time programming

Follow this order without skipping ahead:

1. [Programming foundations](./00-Foundations/README.md) — problem statements, pseudocode, flowcharts and dry runs.
2. [Java basics](./01-Java-Basics/README.md) — syntax, variables, input/output, conditions, loops and methods.
3. [Complexity](./02-Complexity/README.md) — learn to reason about time and memory.
4. [Arrays](./03-Arrays/README.md) — your first major problem-solving topic.
5. Continue using the [course roadmap](./COURSE-ROADMAP.md) and the topic links in the main README.

## Prepare your computer

- Install a supported Java JDK (Java 17 or later is a sensible course baseline).
- Use an editor or IDE such as VS Code with Java support, IntelliJ IDEA Community, or Eclipse.
- Verify in a terminal: java -version and javac -version.
- To compile and run a simple standalone file: javac Example.java then java Example.
- Some files have their own class names and must be compiled from their directory or with the correct file path. Read the source comments and topic README.

## The method to learn each topic

1. Read the topic introduction and objectives.
2. Write key terms and the idea in your own words.
3. Trace the worked example by hand.
4. Implement the basic version yourself.
5. Test a normal case, boundary case, empty/small case where applicable, duplicates and invalid inputs where applicable.
6. Try the practice problems before opening the solution.
7. If stuck: reread the problem, make a small example, attempt brute force, then seek a hint. Avoid copying a solution as your first action.
8. After studying a solution, close it and reproduce it from memory.
9. Revisit it the next day, a week later and a month later.

## How to ask for help (or contribute)

When asking for help, include the exact problem, your code, input, expected output, actual output and error text. Describe what you tried. You will learn more from debugging your own attempt than from pasting a finished solution.

## Practice and mastery

Use [LeetCode & interview practice](./LEETCODE.md) as an index. Its status labels distinguish a planned problem from an independently reproduced or repository-verified solution. Do not interpret a listed problem or company tag as verified unless the index explicitly says so.

Use [PROGRESS.md](./PROGRESS.md) to track your own learning. Check a box only after completing the mastery gate—not just after reading a file.

## Course status and transparency

This is a growing open course. The overall topic map is broader than the currently fully developed teaching lessons. Some code is still under review; automated compilation and selected regression tests do not prove every solution correct. The [repository audit](./REPOSITORY-AUDIT.md) records known verification work. Please report broken links, unclear explanations or bugs using a GitHub issue.

## Suggested weekly plan for a beginner

- 4 study days: learn a concept and solve 1–3 problems at your current level.
- 1 day: revisit older problems without notes.
- 1 day: short timed quiz or mixed practice.
- 1 day: rest or light revision.

Slow, consistent practice is better than racing through the syllabus.
