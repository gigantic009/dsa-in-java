# How to Learn DSA from This Repository

## The active-learning loop
For every topic, use this sequence:

1. **Learn (20–40 min):** Read its lesson carefully.
2. **Recall (5 min):** Close the README and write the main idea from memory.
3. **Trace (10 min):** Work through a hand example using a table.
4. **Implement (20–45 min):** Write code without copying.
5. **Test (10 min):** Normal, edge, boundary and adversarial cases.
6. **Solve (30–90 min):** Attempt one or more new problems.
7. **Explain (5 min):** Explain the algorithm, invariant and complexity aloud.
8. **Review:** Revisit tomorrow, after a week, and after a month.

## Rules for solutions
- Give each problem at least 20–30 minutes of honest effort (adjust for beginner difficulty).
- Write down what you tried and where you got stuck.
- Read a hint before reading the full solution.
- After reading, close the source and implement from memory.
- Re-solve the problem later without notes.
- Don't measure progress only by solved counts.

## Weekly rhythm (flexible)
- 4 days: new concepts + problems
- 1 day: mixed revision
- 1 day: timed test
- 1 day: rest or light review

## Problem journal template
For each problem record:
- Title and topic/pattern
- What is being asked?
- Brute-force idea
- Optimized idea and why it works
- Algorithm / invariant
- Complexity
- Edge cases
- Mistake made
- Date solved and next review date

## When to move forward
Do not move on because you watched/read the explanation. Move on when you can implement, test, and explain it independently. If you fail the checkpoint, review the lesson and practice again.
